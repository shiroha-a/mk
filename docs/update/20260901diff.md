## 移植優先度: 高

### 1. `federation/update-remote-user` の認証・scope・レート制限 (SEC, fork merge)

- upstream: `ab6d188f6c`。`requireCredential: false` でレート制限も無く、未認証で任意のリモートユーザーの再取得を無制限に起こせた。修正後は `requireCredential: true` / `kind: 'read:account'` / `limit: 1 時間 30 回`

**mk-go は部分対応。** #2106 で `RequireAuth()` を付けていたので未認証では叩けないが、scope もレート制限も無く、ログインしていれば無制限に強制再取得 (`ForceResolveActor` は TTL を無視する) を起こせた。

- 対応: `RequireScope("read:account")` と `ratelimit_defs.go` への登録 (1 時間 30 回)。`app_token_scope_gate_test.go` の除外 (理由が「upstream は requireCredential:false」) を外す
- **golden が動く**: submodule bump で `golden_permissions.json` が `public` → `auth`、`golden_oauth_kinds.json` に `read:account` が加わる。追従 PR で一緒に入れる
- frontend の `get-user-menu.ts` に `$i != null` の条件が入る (submodule bump で入る)

### 2. WebSocket の subNote 購読数 (SEC, fork merge)

- upstream: `ba7f23ab03`。1 接続あたりの subNote に上限が無く、dispose でも listener を外していなかった。修正後は 1536 件の LRU と dispose 時の解除

**mk-go は未対応だった (#3175 で対応済み)。** 切断時の解除はできていたが件数の上限が無かった。mk-go は購読 1 件ごとに Redis の接続を張るので、upstream より値を小さく (128、チャンネルのトピック上限と同じ) して、古いものから外す。

### 3. 招待コードの確保 (SEC, fork merge)

- upstream: `1967f80d24`。招待コードの検証 (読み取り) と消費の間に隙間があった。修正後は作成の前に条件付き UPDATE で確保 (`claimRegistrationTicket`) し、失敗したら戻す (`releaseRegistrationTicket`)

**mk-go はメール確認の経路が既対応 (#604 の `FOR UPDATE`)、メール確認なしの経路が未対応だった (#3175 で対応済み)。** upstream と同じ条件の確保 / 解放を両経路に入れた。

## 移植優先度: 中

### 4. リモートノート掃除のカーソルを保持する

- upstream: `1510c443cd` (#17957)。走査カーソルを Redis の `cleanRemoteNotes:cursor` に保存し、ジョブをまたいで再開する。末尾まで進んだら消して次回は先頭から

**mk-go は未対応で、upstream より症状が重い。** `DeleteExpiredRemoteNotes` (`internal/repository/note.go`) は実行中のカーソルすら持たず、`ORDER BY` も `id > cursor` も無い `LIMIT` だけ。保護対象 (ローカルの返信など) を含むツリーは毎回同じ根として選ばれて枠を食うので、それが 100 件以上あると掃除が進まない。

- 対応: repo に `after` (カーソル) を渡して `id > ? ORDER BY id` にし、processor が同じキー (TS と入れ替えても互換) を読み書きする。難易度 M

### 5. チャートの値を列の範囲で頭打ちにする

- upstream: `70506ec9a3` (#17931)。smallint / integer の列が上限に達すると UPDATE 全体が失敗し続けていた。修正後は `LEAST` / `GREATEST` で頭打ちにし、バッファの切り離しとチャート単位の try/catch も入れた

**mk-go は部分対応。** バッファの肥大とチャート単位の分離は `maxSaveAttempts` / `requeueFailed` で別の形で対応済み。**値の頭打ちは未対応**で、`ApplyDeltas` は `"c" = "c" + ?` のまま。

- 対応: small / medium の列は `LEAST(... , max)` / `GREATEST(... , min)`、cardinality / accumulate のコピーは Go 側で clamp。`sqlbind-check` が `ApplyDeltas` の書式を pin しているので更新が要る。難易度 M
